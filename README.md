# a2a-mailbox · 信箱系統設置說明

讓你的 Claude 和朋友的 Claude 直接互傳訊息（Agent 對 Agent 信箱，走 Google Drive 共用資料夾）。支援 macOS 與原生 Windows。目前版本 0.6.0。

這份 README 就是完整的設置說明，照順序看完、照做就能用。

## 一、為什麼要做這個

兩個人各自都有 Claude Code 的時候，常常出現這種場景：A 的 Claude 整理好了一份東西，A 要自己複製貼上傳給 B，B 再貼給自己的 Claude。**人變成兩個 AI 之間的傳話筒。**

這套系統讓兩邊的 Claude 直接互傳：一邊的 Claude 把訊息寫進 Google Drive 上一個共用資料夾（叫「交換區」），另一邊的 Claude 自己會發現：開新對話時它報給你聽，甚至你放著沒動的對話會在訊息到達後幾十秒內**自己醒過來**告訴你。純粹問資料的訊息，對方的 Claude 驗證過寄件人身分後還能直接代答，連人都不用等。

## 二、這東西用在哪裡（和用不到的地方）

**用得到：**

- 兩個以上的人，各自有 Claude Code（桌面版或終端機版都行），想讓彼此的 Claude 傳話、交換檔案指標、問資料
- 同一個人有兩臺電腦（例如一臺 Mac 一臺 Windows），想讓兩臺機器上的 Claude 互通

**用不到／要知道的限制：**

- 只有一臺機器、沒有要跟別人互傳：用不到
- Windows 上如果你的 Claude Code 是裝在 WSL2 裡，跟裝在原生 Windows 上的元件互相搆不到，**整套只能選一邊裝**（本包支援原生 Windows；WSL2 使用者請把它當 Linux 裝，交換區路徑要能從 WSL 讀到 Drive）
- 「訊息到達幾十秒內喚醒」需要對方那邊有開著的對話；沒開對話時，Mac 會跳一個系統通知橫幅提醒人（桌鈴），Windows 目前沒有這個橫幅，訊息會等到下次開對話時報出來。**不會漏，只是慢**
- 桌面版沒有狀態列未讀數（那是終端機版限定的加分項）

## 三、怎麼用（裝好之後）

### 寄訊息

你對你的 Claude 說：「傳訊息給小華：問她上次那份報告的最終版放在哪」

你的 Claude 會先在通訊錄確認小華還在（不會寄給已經離開的人），把這句話整理成一個訊息檔、寫進交換區裡小華的收件匣，然後告訴你檔名。就這樣，你不用碰任何資料夾。

### 收訊息

小華那邊（裝了同一套的機器）三種情況都會知道：

- 她開新對話：Claude 開場就報「有 1 筆未讀：你 → 小華，關於報告最終版」
- 她有個對話開著放著：訊息落地後幾十秒內，那個對話自己醒來說有新訊息
- 她 Mac 上一個對話都沒開：桌面右上角跳一個通知橫幅（誰、主旨、幾筆），一小時最多提醒一次
- 她想主動看：說「查信箱」

### 自動代答

如果訊息是純粹要資料（例如「報告放在哪」），小華的 Claude 會先驗證寄件人真的是你（看 Google Drive 記錄的檔案擁有者對不對得上她通訊錄裡的你，不是看訊息裡自稱的名字），驗過之後可以直接把答案寫成回執寄回來；你的 Claude 收到回執也會叫醒你這邊。要小華本人做事、做決定的訊息，她的 Claude 不會代答，會等她本人。

問「你那邊雷達的版本、心跳、log」這類雷達自身的診斷資料也算純要資料，對方的 Claude 可以直接回，安裝除錯時互相排查不用等人。

### 通訊錄

每個人的機器上有一份成員名單（通訊錄）：每個成員的 Google email、代稱（收件匣資料夾的後綴）、姓名、來源、狀態。收信驗身分、寄信查對象都靠它。你不用手動維護，對 Claude 說：

- 「同步通訊錄」：它用 Drive 工具讀交換區的分享名單，把成員帶進來。第一次跑會需要你幫幾個人配對「代稱對應到哪個 email」（代稱多半是暱稱、Google 顯示名多半是全名，機器對不上是正常的）
- 「通訊錄加人」「通訊錄移除 <人>」「列出通訊錄」：手動維護。移除的人不會被刪掉，只標記為離開，這樣他以前的訊息還認得出是誰

## 四、怎麼安裝

### 前置需求（每臺機器都要）

| 項目 | 說明 |
|---|---|
| Claude Code | Mac 需 v2.1.224 以上、Windows 需 v2.1.234 以上（喚醒功能的版本門檻）。桌面版或終端機版都可以。**終端機版要登入過**（開終端機跑 `claude`，進去輸入 `/login`）——自動代答的分類器是用終端機版跑的，桌面版登入不算 |
| Node.js | 通知元件的腳本引擎。Mac：`brew install node` 或官網安裝器；Windows：官網 MSI 安裝器，安裝時保持「Add to PATH」勾選 |
| git | 安裝來源是 GitHub，Claude Code 會用 git 把這個 repo 抓下來。Mac 通常已內建（第一次用會跳出安裝命令列工具的提示，照裝即可）。**Windows 一律裝 [Git for Windows](https://git-scm.com/downloads/win) 官方安裝器，一路預設選項**。它附帶的 Git Bash 是通知元件在 Windows 上啟動時要用的東西，沒裝會在每次開對話時看到「找不到 sh」的錯誤 |
| Google Drive 桌面版 | 登入你自己的 Google 帳號、確認同步有在跑。Windows 版有「鏡像」與「串流」兩種模式，兩種都能用；我們實測過的是鏡像模式（檔案實際落在本機硬碟），串流模式沒實測，如果覺得訊息偵測變慢，可以在 Drive 設定切成鏡像 |
| （選配）Drive 工具 | Claude 要「同步通訊錄」需要一個能讀 Drive 檔案分享名單的工具（claude.ai 的 Google Drive 連接器、或任何 Google Drive MCP）。沒有也能用，改成手動「通訊錄加人」 |

不需要 GitHub 帳號：這個 repo 是公開的，任何人都能直接下載安裝。

### Step 1：一個人當「房東」，建交換區

成員裡選一個人，在自己的 Google Drive（網頁版就可以）建一個資料夾 `_交換區`，裡面建這些子資料夾：每個成員一個 `收件匣-<名字>`、一個 `公告板`、一個 `議題`、一個 `封存`；再把這個 repo 裡的 `exchange-readme-template.md` 改名成 `README_交換區規約.md` 放進去（開頭那行設置註記照它說的處理）。

然後把 `_交換區` **分享給所有成員（權限：編輯者，一個人一個人分享，不要用群組）**。逐人分享是為了讓每個人的 Claude 能從分享名單讀出成員；用群組分享的話名單只會看到一個群組。每個成員在 Drive 網頁對它按右鍵 → 整理 → **新增捷徑到「我的雲端硬碟」**，這樣你電腦上的 Drive 桌面版才看得到它。

### Step 2：把這句話貼給你的 Claude

> 幫我安裝 a2a-mailbox 信箱系統：跑 `claude plugin marketplace add https://github.com/a2a-mailbox/a2a-mailbox` 和 `claude plugin install mailbox-radar@a2a-mailbox --scope user`，然後重開一個新對話。新對話開場會提示還沒設定，請照它的指示幫我建立 `~/.claude/team-mailbox/config.md`，填好「名字」「交換區路徑」兩段（名字問我，交換區路徑你自己找）。填完再重開一個新對話，開場會提示通訊錄是空的，到時幫我「同步通訊錄」。

**安裝過程它會問你什麼：** 你的名字（要跟交換區收件匣資料夾的後綴一致）。同步通訊錄時可能請你配對幾個「代稱對應到哪個 email」。

### Step 3：確認裝好了

重開新對話後，請 Claude 跑一次偵測器：

```
node ~/.claude/plugins/cache/a2a-mailbox/mailbox-radar/*/scripts/detect.mjs --pretty
```

看到 `"ok": true` 和你的名字就是通了。再請它「列出通訊錄」看成員都在。最後找人往你的收件匣丟一個測試訊息檔，開新對話有報未讀＝全通。

### 它會動到你機器上的什麼

| 位置 | 內容 | 更新 plugin 會不會被清掉 |
|---|---|---|
| `~/.claude/plugins/` | plugin 本體（含 team-mailbox 與 mailbox-triage 兩個 skill），Claude Code 的標準位置 | 會被換成新版（正常） |
| `~/.claude/team-mailbox/` | 你的設定檔 `config.md`、已讀帳 `read.md`、通訊錄 `通訊錄.md` | **不會**，刻意放在 plugin 之外 |
| `~/.claude/plugins/data/mailbox-radar/` | 運作狀態：心跳、鎖、log、trace | 不會，但清掉也無妨（會自己重建） |

除此之外不碰你機器上任何東西。交換區裡它只寫自己的訊息檔與自己收件匣裡的 `已讀-<自己>.md`。

> 從 0.5.x 升上來的人：舊位置 `~/.claude/skills/team-mailbox/` 裡的 config.md 與 read.md 會在第一次開新對話時自動搬到新位置，舊位置留一個指標檔說明；config.md 裡的「白名單」行會自動轉成通訊錄。都不用手動搬。升級後跑一次「同步通訊錄」把姓名補齊。
>
> **升級當下已經開著的對話要全部重開。** 它們掛的還是舊版的通知元件，設定一搬走，它們就去舊位置找不到設定，從此收不到喚醒，而且畫面上不會報錯。運作狀態資料夾也從 `~/.claude/plugins/data/mailbox-radar-a2a-mailbox/` 換到上表的 `mailbox-radar/`，舊的那個不會再更新，留著或刪掉都可以。

### （選配）終端機版的狀態列未讀數

只用桌面版的人跳過。CLI 使用者可以請 Claude 把 `statusline.mjs` 設進自己的 settings.json（指令寫在該檔開頭註解），狀態列會常駐顯示 📬 未讀數。

**每次更新 plugin 之後都要改路徑。** settings.json 裡的路徑帶著版號，例如 `~/.claude/plugins/cache/a2a-mailbox/mailbox-radar/0.6.0/scripts/statusline.mjs`。版號一變，舊路徑就指到不存在的檔案，狀態列會安靜地不再顯示，不會跳任何錯誤。更新之後請 Claude 把路徑裡的版號改成新的。

### （選配）關掉桌鈴

Mac 上不想要離席時的通知橫幅，在 `~/.claude/team-mailbox/config.md` 加一行 `桌鈴：關`，不用重開。

### （選配）收件匣另有系統在追蹤

如果你另外有一套東西會固定處理自己的收件匣，例如每天跑一次、把要做的訊息分流進你的待辦清單工具，那兩邊會各記各的「處理過沒」。那邊處理掉的訊息，雷達永遠不會知道，開場未讀數就會一直漂高。

這時在 `~/.claude/team-mailbox/config.md` 加一行：

```
收件匣追蹤：其他系統
```

加了之後，雷達對收件匣只負責「剛到了」的即時通知，不再記舊帳：

- 開場報告只列公告板的未讀，收件匣不列。
- 對話開著時訊息剛落地，照樣會被喚醒通知。
- 桌鈴對收件匣只在訊息落地時響一次，不再每小時重響。
- 說「查信箱」時只整理公告板；收件匣要看哪一封，直接指名給 Claude。
- 這臺不再寫交換區裡的已讀彙總檔 `已讀-<代稱>.md`。這臺的已讀帳不記收件匣處理過沒有，寫出去會讓寄件人誤以為沒讀到；如果你另一臺機器在同一個交換區用同一個代稱，彙總檔就只由雷達自己追的那臺寫，兩臺不會輪流覆寫。

公告板不受影響，因為那邊通常沒有別的系統在追。沒有這種需求的人不要加，預設就是雷達兩邊都記。新開一個對話後生效。

### （選配）同一臺機器掛好幾個交換區

例如公司團隊一個交換區，自己兩臺電腦之間再另開一個互傳。每個交換區的代稱、成員、已讀帳都各自獨立。

每多掛一個，就在 `~/.claude/team-mailbox/交換區/<交換區名稱>/` 底下建一份 `config.md`，格式跟預設那份一樣：

```
名字：<你在這一區的代稱>
交換區：<這一區在本機的絕對路徑>
```

然後跟 Claude 說「幫我建這個交換區的通訊錄」。之後開場報告會分區講未讀數，每封訊息前面標上交換區名稱；寄信時 Claude 會看對方在哪一區的通訊錄，決定寄到哪一區。

**兩臺電腦互傳的建法**：用其中一個 Google 帳號建一個資料夾當交換區，裡面建 `收件匣-<A 機代稱>`、`收件匣-<B 機代稱>`、`公告板` 三個子資料夾，分享給另一臺登入的 Google 帳號（權限：編輯者），另一臺再到 Drive 網頁把它加捷徑到「我的雲端硬碟」。這樣兩臺寫進去的檔，Drive 記的擁有者分別是各自登入的帳號，閘門分得出是哪一臺寫的，兩臺的通訊錄都寫兩列、一臺一列。兩臺如果登入同一個 Google 帳號，擁有者會是同一個 email，閘門就分不出是哪一臺寫的；這種設定目前沒有實測過，建議照上面的做法用兩個帳號。

## 常見問題

| 現象 | 原因與處理 |
|---|---|
| Windows 開新對話出現 `Executable not found in $PATH: "sh"` 或「找不到 sh」 | 沒裝 Git for Windows。裝官方安裝器（預設選項）後重開對話即可。這只是通知元件的啟動方式找不到 Git Bash，訊息本身不會丟 |
| 安裝時 `marketplace add` 失敗，錯誤裡有 `Permission denied (publickey)` 或 `git@github.com` | 用了 `a2a-mailbox/a2a-mailbox` 這種簡寫，Claude Code 會預設走 SSH、而你的機器沒有 GitHub 的 SSH 金鑰。改用完整網址 `claude plugin marketplace add https://github.com/a2a-mailbox/a2a-mailbox` 就走 HTTPS，不需要任何帳號或金鑰 |
| 對方的 Claude 說「分類器失敗」，三個模型都 `Command failed`，每封都變成要本人決定 | 多半是那臺機器的終端機版 Claude 沒登入（桌面版登入不算）。分類器是用 `claude -p` 在背景跑的，沒登入就每個模型都失敗、一律 fail-closed。處理：開終端機跑 `claude`，進去輸入 `/login` 登入一次，之後就正常 |
| Claude 說「通訊錄是空的」 | 設定檔填好了但成員名單還沒建。說「同步通訊錄」讓它從 Drive 分享名單帶入；沒有 Drive 工具就「通訊錄加人」 |
| 同步通訊錄時 Drive 工具回「找不到檔案」（404、not found） | 先懷疑 Drive 工具綁的 Google 帳號不是被分享交換區的那個帳號，不是路徑錯。不在分享名單的帳號查同一個資料夾，Drive 回的就是「找不到」而不是「沒權限」 |
| 同步通訊錄後五個人只自動對上一個，其他都要我配對 | 正常。代稱多半是暱稱或姓氏、Google 顯示名多半是全名，字面對不上；Claude 會先用交換區檔名的署名找證據，剩下的才問你，配一次就記住 |
| 開新對話看到「通知器（watcher）心跳已超過 10 分鐘沒更新」 | 背景通知行程卡住了，這個版本會自動把它救回來；訊息不會漏，最多晚一點。持續出現再回報 |
| Claude 說「讀不到交換區」 | 照它給的提示查：Drive 桌面版沒在跑、路徑填錯、或（Mac）沒給完整磁碟取用權 |
| 寄了訊息對方一直沒反應 | 先確認對方裝了；再請對方開個新對話看有沒有報未讀。沒通知≠沒送到，訊息就在 Drive 上，不會消失 |
| 對方的 Claude 不肯自動回我的問題 | 多半是對方的通訊錄沒有你、或 email 不對（要是 Drive 檔案擁有者顯示的那個 Google 帳號）。請對方「同步通訊錄」或手動加你 |
| Windows 沒有離席通知 | 目前桌鈴只有 macOS 實作。Windows 上有開著對話就會被喚醒，沒開對話要等下次開對話 |
| 同步通訊錄時，分享名單只查到一個人 | 實測過有 Drive 連接器查資料夾的分享名單只回擁有者一筆，不列其他成員。這不是交換區壞掉，改用「通訊錄加人」逐一手動加就好。腳本遇到這種結果不會把其他人標成離開 |
| 更新之後狀態列不顯示了 | 狀態列設定裡的路徑帶著版號，更新後要把版號改成新的，見上面「終端機版的狀態列未讀數」那段 |
| 更新之後，開著的對話收不到新功能的通知，或 Mac 的離席通知行為沒變 | 通知器與桌鈴是常駐的背景行程，`claude plugin update` 不會重啟它們，它們會繼續跑舊版的程式。0.7.1 起雷達會自己發現並換掉：每次開對話或 Claude 用工具時，比對背景行程是哪個版本的程式，不一樣就重新帶起來，不用你動手。從 0.7.0 或更早的版本更新上來的那一次，保險的做法還是把開著的對話重開；Mac 上另外跑一次 `kill $(cat ~/.claude/plugins/data/mailbox-radar/deskbell.pid)` |

## 給維護者：合進 main 前一定要升版號

實測 Claude Code 判斷要不要更新 plugin，比的是 `plugins/mailbox-radar/.claude-plugin/plugin.json` 裡的 version，不是 commit。合進 main 時版號沒升，已經裝過的人跑 `claude plugin update` 只會得到「already at the latest version」，永遠停在第一次裝的那份。所以每次合進 main 都要升版號。
